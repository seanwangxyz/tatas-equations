# A11Y: easier on the eyes

Patterns on the cubes for colour-blind players, high-contrast colours, a larger-text option, calmer effects,
keyboard focus and touch-size fixes. Owner-approved task: "Easier on the eyes."

## Files

| File | What |
|---|---|
| `js/a11y.js` (new) | Reads `S.set`, puts classes on `<html>`, draws patterns for canvas textures, the Settings group, the dev colour-vision filter, keyboard / aria fixes |
| `css/a11y.css` (new, loads LAST) | Flat cube patterns and letters, zone edges, On-Sets dot shapes, high-contrast colours, text size, calm, focus rings, touch sizes |
| `js/three/table.js` | Blocks marked `A11Y` only: `drawFace` (pattern + high-contrast colours), `atlasTex` / `d20Tex` cache keys, the d20 rim marks, the zone outlines and zone label size in `buildTable` |
| `js/three/replay.js` | `standInTex`: pattern + high-contrast colours (marked `A11Y`). The replay's real cube copies share the table's textures, so they follow automatically |
| `js/three/varilabels.js` | Variation label height follows the text size (one line, marked `A11Y`) |

The title scene's cubes use `T3.drawCubeFace`, so they get the patterns too (on the next load of the title scene).

### Reduce flashing: `S.set.calm`

Read it with `window.A11y && A11y.calm()` (or `S.set.calm === true`). What already follows it:
- Everything that checks `matchMedia('(prefers-reduced-motion: reduce)')` in JS: with calm on, a11y.js makes that
  query report a match. So `js/fx.js` (fewer confetti / bursts / fireworks), `js/three/fireworks.js`, the replays
  (still picture) and the 3D title (still frame) all tone down with no change in their files.
- `css/a11y.css`: the orbit photo's white `.orbit-flash` is hidden, the intro's bright "shine" is dropped, highlight glows are softer, the confetti canvas is 70% opacity.

Still to read it (owners): `js/three/table.js` `api.fx('flash')` / the venue's `env.flash()` (stadium camera
flashes: skip when `A11y.calm()`), and the CSS-only `@media (prefers-reduced-motion)` blocks do not see the flag
(add `html.a11y-calm` selectors next to them if they matter).

## The patterns (and why)

Each cube colour has its own six faces, and variation cards / On-Sets talk about colours, so every colour got a second
cue that does not depend on hue:

| Colour | Pattern | Letter | Why |
|---|---|---|---|
| red | a solid triangle in the top-left corner | R | one bold shape, away from the symbol; reads even when the cube is small |
| blue | horizontal stripes (faint across the middle) | B | stripes survive blur and distance |
| green | a grid of dots (bolder at the edge, faint in the middle) | G | texture clearly unlike stripes |
| black | a checked edge all round | K | black is the darkest already; the checker frames it so it never reads as dark blue |
| Power die (d20) | a double rim inside each triangle | | Power vs Big-number already differ in lightness and labels |
| Big-number die (d20) | a dotted rim | | |

Patterns sit mostly at the edges and are faint where the symbol is, so the big symbol stays the clearest thing (checked
in every skin: classic, candy, lava, galaxy, gold; on light skins the pattern ink turns dark). Letters sit in the top-right
corner, small, outlined.

**Zones**: Required = solid edge, Permitted = dashed, Forbidden = dotted plus a faint diagonal hatch (flat mat and 3D felt).
**On-Sets** dots: B circle, R square, G triangle, Y diamond (+ letters with "Patterns + letters"), pure CSS on the existing
`.os-card .d-*`, `.os-dot.d-*`, `.os-tilecards .d-*`. No JS change needed in the flat On-Sets files.
**Other colour-only signals**: the player whose go it is gets a double ring (it already says YOUR GO), a shake-winning
score line gets a star, season form chips get shapes (they already have W / D / L), the chosen kit colour gets a tick,
and a long press on a kit colour shows its name (they already have title / aria-label for hover and screen readers).
Weather, variation and Twist chips already carry icons and words, so nothing needed there.

**High-contrast colours** (`palette: 'contrast'`): red-orange `#ff8a3d→#c44d00`, blue `#3a66d8→#0f2a78`, light green
`#9af7d4→#2cc48f` with a dark symbol, black `#4a4a4a→#000`. After the Okabe-Ito colour-blind-safe set, spread in
lightness (black < blue < red-orange < green) so they also part in greyscale. On-Sets tokens `--osB/--osR/--osG/--osY`
change with it. It also darkens the white-text buttons to AA.

## Hooks for the On-Sets 3D rebuild

```js
// a colour dot on a canvas face (cx, cy centre, r radius), keeping your own fill colour:
g.fillStyle = myColour[c];
if (window.A11y && A11y.patterns()) A11y.drawDot(g, c, cx, cy, r);   // circle / square / triangle / diamond for B / R / G / Y
else { g.beginPath(); g.arc(cx, cy, r, 0, 6.283); g.fill(); }
if (window.A11y && A11y.letters()) { var m = A11y.dotShape(c); /* draw m.letter small, centred on the dot */ }
// a cube face in one of the four Equations colours: draw your background, then
if (window.A11y) A11y.drawFacePattern(g, 'red', 128);                // pattern (+ letter); draws nothing when helpers are off
// cache keys: add A11y.key() to any texture cache key that uses the above
// redraw when a setting changes:
window.addEventListener('a11ychange', function () { /* dispose cached textures, rebuild */ });
// label sizes: multiply canvas text heights by (window.A11y ? A11y.textScale() : 1)
// high-contrast hues: A11y.faceCols('red') -> [light, dark, ink] or null
```
`A11y.dotShape(c)` returns `{shape, glyph: '●'|'■'|'▲'|'◆', letter, name}` for text use (e.g. a 2D legend).

## Dev: colour-vision simulation

`?cvd=protan`, `?cvd=deutan`, `?cvd=tritan`, `?cvd=grey` puts an SVG colour matrix (Machado et al. 2009, full
severity, linear RGB) over the whole page, the 3D canvas included. `A11y.cvd('deutan')` / `A11y.cvd('none')` switch
it live. Nothing in the game links to it.

What the match screenshots showed (1280x800, 3D, classic skin, no real colour-blind testers):
- **Helpers Off**: deutan and protan: red and green cubes become the same olive (protan red also close to black);
  tritan: blue and green cubes both teal; greyscale: red, blue and green the same grey. The three zones differ only
  by their words in every mode.
- **Helpers On**: in all four modes each colour is told apart by its pattern (corner / stripes / dots / checked edge),
  and the zones by solid / dashed / dotted+hatch. At table distance the red corner and the black checker are the
  easiest to see; green dots are the subtlest (bolder edge dots were added after the first look). Letters are small at
  table distance (fine close up and on the flat cubes).
- **High-contrast + helpers, greyscale**: black < blue < red-orange < green in lightness; blue vs black is the closest
  pair, separated by stripes vs checker.
- On-Sets cards: R vs G (deutan / protan) and B vs G, Y vs R (tritan) become alike in colour; the shapes separate them.

## Text size audit

Method: every screen (title, setup, trophies, stats, settings, daily, camp, cup, season, fans, On-Sets, gift) opened at
Normal / Large / Extra large at 1280x800, 1024x768 and 390x844 (phone sizes in a same-origin iframe), checked by
script for horizontal overflow, boxes off the screen and clipped text; plus screenshots of a match (3D) at each size,
the builder pop-up on the phone, and the Settings group.

- 1280x800 and 1024x768: no overflow at any size after the fixes. The match's right-hand column widens with the text
  (Large 300-400 px, XL 320-440 px); the iPad bottom bar fits.
- 390x844: fixed in a11y.css: title modes one column at XL, opponent / camp / cup cards one column at XL, season table
  drops the P column and avatars at XL, match score pills drop the jersey badge so names fit (Large, XL).
- Left (other owners' files):
  - `css/title.css` `#title .mm-hero .btn.big` (the big Play button) clips its second line by ~8 px at XL on a phone.
  - At XL on a phone the second player's name in `.game-top .pl b` still truncates with an ellipsis ("Play…").
  - The stadium big screen text (`env.setBoard`) and the commentary caption are not scaled.
- How it scales: style.css and the other sheets are all px, so a root rem token cannot reach them. Pages and pop-ups
  use `zoom: var(--ts)` (keeps their proportions; browser zoom still works on top). In the match only the text panels
  (scores, Goal, Pip's line, buttons, chips) scale, not the 3D picture; the 3D zone labels and variation labels get the
  same factor. Note for anyone styling a zoomed box: its own px and vw lengths are multiplied by the zoom, so a11y.css
  writes those widths as `length / var(--ts)`.

## Problems found in files I do not own

- `css/style.css` `@media (prefers-reduced-motion:reduce){ *,*::before,*::after{animation-duration:.001s!important ...} }`:
  `.banner` (NOW! / IMPOSSIBLE! / GOAL) uses `animation: bannerIn ... both`, which ends at `opacity:0`, so for
  reduced-motion players the banner is invisible for its whole 1.4 s. Suggest `.banner{animation:none}` inside that block
  (game.js removes it after 1.4 s anyway). The same applies to any one-shot animation whose last keyframe hides the element.
- Candy skin: `.skin-candy .cube` (style.css) and the candy branch of `drawFace` (table.js) draw white symbols on pastel
  stripes, about 1.3-1.6:1. Hard to read for everyone; a dark symbol (like the gold skin) would fix it.
- `css/style.css` `.paren` in the builder is 22 px wide (tap target under 44 px).
- 3D table cubes are canvas: there is no keyboard path to pick and move them (out of scope here).
